**实验协议草案 v0.1：同等每轮期望等待下，重试抖动幅度对故障恢复的影响**

日期：2026-11-11。当前状态：已设计，尚未实现模拟器、尚未运行正式实验。本文是实验协议，不是实验结果或课程报告。

研究对象是多个客户端请求一个海温数据查询接口。查询是只读操作。接口暂时不可用，恢复后处理能力和等待队列有限。全部使用 Python 离散事件模拟；无需联网服务、真机、GPU 或真实海洋观测数据。

用户给出的研究判断是：低负载时固定等待可能已经足够；优先减少截止时间前仍未成功的客户端。第二条确定评价目标，第一条作为需要检验的预测，不作为已知事实。

课程对应：[《让重复迟到失败都变得无害》幻灯片9—10](<D:/活动策划/26-27-1/海洋数据挖掘技术/课件资料/2026_11_10_drive-download-20261103T091257Z-1-001/第2讲_让重复迟到失败都变得无害.pptx>)，指数退避、随机抖动和重试风暴。已有方法参考 [AWS：Exponential Backoff And Jitter](https://aws.amazon.com/blogs/architecture/exponential-backoff-and-jitter/)。本实验采用有限队列服务模型，与该文的并发写冲突模型不同，不直接比较其性能数值。

主实验检验两个预先指定的假设。设 r(a,L) 是抖动幅度 a、负载 L 下跨重复试验的平均未按期完成率。

- H1：高负载下，中等抖动优于无抖动，即 d_H = r(0,H) - r(0.5,H) > 0。
- H2：这一改善在高负载下更大，即 d_H - d_L > 0，其中 d_L = r(0,L) - r(0.5,L)。
- 大幅抖动 a=1 是预先安排的探索对照，不在看到结果后替换 H1 中的 a=0.5。

**服务与客户端采用以下统一规则。**

| 项目 | 预设值或规则 |
|---|---|
| 低负载 | 5 个客户端，各有一个请求任务 |
| 高负载 | 100 个客户端，各有一个请求任务 |
| 首次请求 | 所有客户端在 t=0 发起 |
| 故障恢复时刻 R | 每轮独立采样 Uniform(2,4) 秒，同轮所有策略共享 R |
| 服务故障期间 | 立即拒绝请求；客户端在请求发出后 0.02 秒收到失败响应 |
| 恢复后处理能力 | 单个工作器，每个请求处理 0.05 秒，即最多约20个/秒 |
| 等待队列 | FIFO，最多5个等待请求，不含正在处理的1个 |
| 恢复后队列已满 | 拒绝；0.02秒后返回失败响应 |
| 已接纳的请求 | 排队或处理期间客户端不重试；完成后收到成功响应 |
| 共同截止时间 D | t=12 秒，从首次请求起计时 |
| 尝试次数上限 | 每客户端20次，包含首次请求 |
| 未按期完成 | t=12 时仍未成功；包含提前耗尽尝试次数的任务 |
| 客户端可见信息 | 自己的尝试次数、响应与时间；不告知恢复时刻 R 或其他客户端状态 |

截止时间不是从每次失败后重新计时。t<D 时可以发起尝试；在 t<=D 完成的请求记为成功。每客户端只有一个未完成请求，不模拟单次请求超时、响应丢失或重复执行副作用。

同一时刻先处理完成事件，再处理新请求；同时到达的请求使用同轮共享的随机优先级处理。故障期间不把请求积压在服务端队列。被拒绝请求的服务端资源成本在第一版中不建模，只记录请求次数。

高负载100个任务在理想无空转情况下需要5秒处理；最晚第4秒恢复，理论上可在第9秒完成，早于12秒截止。这样避免把物理容量不足误判为重试策略失败。

**三种策略只改变抖动幅度。**

第 j 次失败后的基准期望等待为：

    b_j = min(0.25 * 2**(j-1), 2.0) 秒，j从1开始。
    W_j(a) = b_j * (1 + a * (2*U_j - 1))，U_j ~ Uniform(0,1)。

| 策略 | a | 每轮等待分布 | 该轮期望等待 |
|---|---:|---|---|
| 无抖动 | 0 | 固定 b_j | b_j |
| 中等独立抖动 | 0.5 | Uniform(0.5*b_j, 1.5*b_j) | b_j |
| 大幅独立抖动 | 1 | Uniform(0, 2*b_j) | b_j |

2秒是基准期望等待的上限，不是所有策略的最大实际等待；大幅抖动的实际等待最大可达4秒。这是均值匹配的实验定义，不能与使用相同上限的标准 Full Jitter 混为一谈。实际总等待、实际尝试次数和成功时刻允许不同，它们是结果，不能为了公平而事后强制配平。

下一次尝试时刻等于失败响应到达时刻加 W_j。若尝试时间达到截止时刻，或次数已用尽，不再发起。

**数据来自模拟器事件记录。**

正式主实验使用200个独立随机种子，每个种子运行两种负载和三种幅度，共1200轮。每轮所有客户端算一个试验单元，不能把其内部的客户端当作独立重复。

每个种子预生成 R、同时到达时的优先级、以及按“客户端编号×失败次数”索引的随机数。主实验不同幅度复用同一个随机数表，只改变幅度映射。环境随机数与重试随机数分开生成，避免策略改变事件数量后连带改变恢复时刻。

保存每轮配置、种子和策略；保存每次请求的客户端编号、尝试编号、发送时刻、接纳/拒绝原因、响应时刻；保存每次失败后的 b_j、随机数、实际等待；保存最终成功时刻或未完成原因。结果表和图由原始事件日志生成，不手工填写。

**评价首先看未按期完成率。**

| 指标 | 定义与作用 |
|---|---|
| 主指标 r | 截止前未成功的客户端数 / 全部客户端数；低负载与高负载用比例比较 |
| 未完成数量 | 每轮同时报告人数，便于解释实际含义 |
| 总请求量 | 截止前发出的所有尝试，包含首次请求与失败请求 |
| 恢复后重试峰值 | 恢复时刻后，任意连续100毫秒内的重试到达数；排除首次请求 |
| T95 | 达成95%客户端成功所需的时间；若截止前未达成，标记为 >12秒，不仅在成功子集中求P95 |
| 拒绝原因分解 | 分别统计服务未恢复与队列已满造成的失败 |

请求数、峰值或T95更好不能抵消更高的未完成率。未完成任务不能从分母移除。峰值使用滑动时间窗，避免固定分桶边界掩盖瞬时集中。

主比较是每个种子的中等抖动与无抖动之间的配对差。以200个种子为重采样单元进行10000次配对Bootstrap，计算 d_H 及 d_H-d_L 的95%置信区间。不能在重采样时打乱同一环境下的配对关系。

H1方向获支持的标准为 d_H 的区间下限大于0；H2的标准为 d_H-d_L 的区间下限大于0。若区间跨过0，记为证据不足，不能说证明两者相同。另建议把 d_H 至少5个百分点作为值得继续探索的实际效果门槛；该门槛是本项目预设，不是行业标准。

**机制实验保持单个客户端的等待分布不变，只改变客户端之间是否共用随机数。**

在高负载、a=0.5下，为200个相同环境种子各增加一个“共享抖动”试验。每个失败轮次 j 的所有客户端使用同一个 U_j；每个客户端该轮仍具有相同的均值与边际分布，但失败客户端仍会成批重试。与主实验的独立抖动比较。因此最小正式实验共1400轮。

去同步机制的预测是：独立抖动相对共享抖动，产生更小的重试峰值、更少的队列满拒绝，进而降低未按期完成率。除汇总值外，画同一环境下独立/共享抖动的重试时间分布和累计成功人数曲线。

若独立抖动并未降低峰值或队列满拒绝，即使主实验有收益，也不能把收益全部解释为打散同步重试。如果峰值下降但未完成率不降，只支持机制的前半部分。

**以下因素会导致不公平比较或错误解释。**

- 直接比较相同等待上限而不同平均等待的策略，把等待时间变化归因于随机幅度。
- 给某策略更多尝试次数、更晚截止时间，或者让每次重试重置任务截止时间。
- 不同策略使用不同恢复时刻、服务容量、队列规则或首次请求时刻。
- 初次请求都同时到达，却把这次公共峰值算成重试峰值，掩盖真正差异。
- 只统计成功客户端的耗时，丢弃超时者；或只比较请求少而不比较成功率。
- 用单个随机种子、按结果挑恢复时刻，或事后把最好的幅度替换为预先指定主比较。
- 统计区间按客户端而不是独立试验种子计算，夸大样本独立性。
- 忽略队列大小、入队与拒绝规则对结论的影响。主结论只适用于本协议的有限队列模型；大队列可作为后续边界测试。
- 宣称每轮均值相同等于整轮实际总等待相同。不同成功时刻会改变后续尝试，实际总等待不能事后固定。
- 将事件模型的模拟秒数当作Python程序墙钟时间，或把合成服务结论直接推广为互联网服务性能。

**否定、收缩与证据不足应分别记录。**

| 观察结果 | 解释 |
|---|---|
| d_H的区间上限<=0 | 反对H1：中等抖动没有降低高负载未完成率，或使其更差 |
| d_H-d_L的区间上限<=0 | 反对H2：高负载收益不大于低负载 |
| 区间跨0 | 证据不足，不自动视作等效或已证伪 |
| d_H>0但幅度很小 | 有方向性收益，实际采用价值有限；不能夸大效果 |
| 仅请求数、峰值变好，未完成率变差 | 不满足用户优先减少超时的目标 |
| 独立和共享抖动表现相近，去同步指标也未改善 | 去同步机制解释未获支持 |
| 只有a=1表现好，a=0.5不支持H1 | 报告探索发现；需要新独立样本验证，不能替换原主假设 |

正式实验前只进行实现自检：没有故障且容量足够时所有任务应成功；服务始终不恢复时所有任务应未完成；尝试次数不得超过20；任何成功完成不得早于服务处理完成；a=0的等待应严格等于b_j；同一输入与种子应可重复得到相同事件日志。发现程序错误后修复并完整重跑，记录版本；不能为获得支持假设的结果调整参数而不披露。

当前实验的贡献定位是课内机制的受控验证与适用边界分析。随机退避本身是已有方法，尚未提出或确认新算法。完成本轮后，再依据失败样本决定是否有必要设计新的策略。
